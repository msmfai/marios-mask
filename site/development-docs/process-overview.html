Process overview

Purpose: show the full process in one figure. Each stage links to the document that describes it.

Summary

One person, the owner, directed the project. AI coding agents did most of the implementation. The owner decided what to build, tested the result by playing it, and decided each release. The agents wrote code, tests and documents inside limits that the owner set.

Each piece of work went through the same stages. Each stage has one actor and one record. The records are in Git and GitLab, not in agent conversations.

Stages

Three loops are not shown in the figure. If the tests fail, the agent goes back to the slice. If the owner finds a fault in play, the fault becomes a new bug report. If the manager or the release gates reject the work, it goes back to the agent.

Branches

  • Release branch. The mod that works on a console. Fixes for the current public release go here. All feature branches start from it.
  • Feature branches. One for each work item. Each has its own worktree and one agent.
  • Import branch. The Super Mario 64 level import. Fixes from the release branch merge forward into it. It gets no public release until the main overworld runs with the same frame rate and free memory as the release branch.

Test order

Tests run from the cheapest to the most expensive. A failure at one level stops the work before the next level.

  1. Build and structural checks
  2. One focused headless scenario for the changed behavior
  3. The standard test suites that apply to the change
  4. Large matrices: geometry, collision and Mario behavior
  5. Owner playtest
  6. Release gates. These run only for a release (document 13).

Developer builds are debug builds by default. Only one guarded build path makes the public release ROM.

Limits

  • Real N64 hardware is the final gate. As of September 2026 no hardware test was recorded, and public alpha releases shipped without one. The owner decided that hardware testing was not a priority before the beta.
  • This process developed over time. Work items and merge requests started in late August 2026 (document 14).
