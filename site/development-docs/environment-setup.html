Mario's Mask builder

Environment setup

Purpose: list the tools, inputs and setup steps for a development machine.

Summary

The development build runs on macOS or on a Debian-like Linux. It needs common build tools, the three original ROMs and the public decompilation projects at fixed commits. A task runner sets up each worktree and runs the builds.

Requirements

ItemRequirement
Operating systemmacOS or Debian-like Linux. On Apple Silicon macOS, Homebrew supplies libpng.
Host toolsBash, Git, Python 3 with venv and pip, curl, rsync, ffmpeg, tar, GNU Make, a C and C++17 compiler
Librarieslibpng, libxml2 and zlib development headers
MIPS toolsGNU binutils 2.42 and GNU libiconv 1.18. The build compiles them if the host does not have them.
ROMsNTSC-US Super Mario 64, Ocarina of Time 1.1 and Majora's Mask. The build checks the hash of each.
DecompilationsThe public SM64, OoT and MM decompilation projects, at pinned commits. The build refuses other commits.
Task runnerjust. Its recipes leave two CPU cores free.
Emulatorares v148, pinned, with automatic updates off

Procedure

  1. Install the host tools and the task runner.
  2. Supply the three ROMs. The build checks their hashes before it continues.
  3. Set up the build root for the worktree. Each worktree has its own root for the MM copy, the SM64 copy, the toolchain and the output. The setup can copy a prepared root from another worktree.
  4. The build clones the decompilations at their pinned commits.
  5. The build extracts assets on the local machine. From SM64 it takes only what the mod needs (for example Mario and Peach textures). From OoT it takes only a few objects and one music sequence.
  6. The build applies the patch series, links the debug ROM and restores the MM copy (see document 6).
  7. Test the debug ROM in ares.

A developer build is a debug build by default. Its title shows "DEBUG". A separate guarded command makes the release ROM.

Recovery

  • The MM copy is disposable. If a build stops before the restore step, run the restore command of the task runner. Do not reset the whole repository.
  • After you stop a build or a search, check the process list. No compiler, converter, emulator or search process may remain.

Emulator setup

  • One pinned ares installation serves all worktrees.
  • A read-only base profile turns on the debug server (GDB), the Expansion Pak and the real boot sequence.
  • Test runs copy this profile into a private folder for each run (see document 7).
  • Controller rule: Xbox A is N64 A, and Xbox X is N64 B.

Agent safety on the host

  • Agents do not search the whole home folder or other large folders. Outside the repository they first find candidate files by name and size, and then search only those files, with a time limit.
  • Agents stop only the processes that they started.

Limits

  • The ares installation and its base profile are part of the machine configuration, not of the repository.
  • The development repository is private. The public repository contains the builder and its recipe, not the mod source.
