Mario's Mask builder

Working model

Purpose: give the division of work between one person and the agents.

Summary

One person directed the project. AI coding agents wrote most of the code. The person did not review every line. Instead, the person decided what to build, and the verification loop decided whether it worked.

Who decides

The owner decidesAgents do
What to build, and what not to buildResearch, code, tests and documents
Every design and creative call: feel, dialogue, presentation, content cutsDiagnosis, with evidence
Whether a fix is verified in playFixes, inside the agreed scope
Every releaseRelease tooling, only on request

The rule: agents ask, never assume. A behavior that looks like a fault can be a deliberate decision. Before an agent changes it, it asks the owner.

One task

A task states:

  • one outcome that a person can see or a test can measure;
  • the evidence that will prove it;
  • what the agent must not do;
  • what the agent may change;
  • when to stop and report.

Large work is cut into slices. Each slice makes one behavior that can be tested alone and leaves the project usable if later slices are cancelled. One 4-day migration without slices was declared a failure at the end.

Stop rules

The agent stops and reports when:

  • it cannot state the acceptance test;
  • the owner corrects the same requirement twice;
  • status checks continue with no new validated result;
  • a fix did not work. Revert it before the next attempt. Never put a second fix on a failed one.

State lives outside the conversation

Long conversations lose accuracy. One session ran 12 days and held 44% of a month's prompts. Project state now lives in commits, work items and documents. Each accepted result ends with a handoff, and the next task starts in a new session.

One agent by default

Several agents ran at once only on work that split into independent parts, each with its own branch, worktree and tests. One manager agent merged the results. Agents that shared an emulator, a branch or build output interfered with each other. Integration also found faults that each branch's tests had missed, for example two branches that used the same dialogue message ID. Merging is work, not a formality.

Structure that makes agent work testable

The host game owns everything: game loop, actors, collision, memory, saves. Imported Mario code reads host state through narrow adapters and writes its result back. All changes are patches applied to a clean copy of the decompiled game. This keeps each change small, reversible, and testable in one place.
