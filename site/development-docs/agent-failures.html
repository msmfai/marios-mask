Agent failure catalog

Purpose: show the failures that are typical for coding agents on this kind of project, and the control for each.

Summary

The agents on this project failed in a small number of repeated ways. Most failures were not bad code. They were wrong conclusions: the agent tested an old build, trusted a proxy, read the wrong source, or kept a fix that did not work. Each failure below produced a rule or a test.

Triage

Most entries below would have been prevented by these checks, in this order:

Class A: stale or wrong build

FailureSymptomCauseRule now
Default test ROM was oldAll 45 areas failed, and the control also failed. Cost: hours, and one change was wrongly cleared.The agent did not name the ROM. The test tool used an old ROM of a different kind.Always name the ROM. Check its time and hash against the build.
Old ROMs in a bisectOld ROMs failed. New builds of the same commits passed.The agent trusted ROMs older than their source.Rebuild before a conclusion. The real faults found later now stop the build.
Regenerated baselineA fix seemed to do nothing: "before" and "after" were the same.The build had already regenerated the baseline with the fix.Build the baseline from the tool version before the fix.
Restore left filesA good build blocked the next build.The restore undid changed files, not files that a patch added.The restore also deletes the files that patches add.

Class B: proxy measurement or no control

FailureSymptomCauseRule now
Proxy count241 defects reported. The real number was 141.The agent counted a related property, not the defect.Measure the exact property. A new gate must fail on the code before the fix.
Model in piecesThe owner saw a broken model in play.The agent checked one of three conversion terms. 73 sites in 26 actors had wrong part positions.Check every term of a conversion. Look at the image.
Cause without controlSeveral "root causes" of a hang looked certain.A healthy build gave the same numbers. One check covered 20 of 35,840 bytes.Run a healthy control and a positive control. State the coverage.
Gate missed a pattern4 actors passed a check that they should fail.The gate matched only literal names, not names made by macros.The gate detects these names. A deliberate fault proves that it fails.

Class C: wrong source of truth

FailureSymptomCauseRule now
One of two registriesThe agent reported that an area shipped 0 of 23 objects, and wrote a checker for it.It read one input and guessed the output. The real stager shipped 21 of 23.Run the real tool. Do not infer output from inputs.
Old comments as truthAn old patch comment was read as current intent.The patch stack is history. The built ROM is the current state.An audit marks old comments. A check fails on an unmarked one.
The gate was wrongCorrect changes were refused, for example "58 of 45" when the true value was 27.Gate tables held old estimates and fixed numbers.Prove what the source does. Then fix the table and record both values.
Wrong start positionThe owner reported that Mario started in the wrong place.The agent used a hand-made value and changed two variables at once.Take the value from the plan record. Change one variable at a time.

Class D: fixes on top of fixes

FailureSymptomCauseRule now
Fall through the worldThe owner saw no change in play.Two fixes shipped without observation. The second fixed the first.Revert to the last state seen working. Instrument before new code.
Crash after scene changeThe crash continued after the fix.The fault was real, but no one proved that it caused the crash.Revert a fix that is only a theory, and any check built on it.
Silent MarioMario had no sound in all original scenes. The report named one place.A function returned 0 when its code was not loaded. Only imported scenes were tested.Test the original scenes too, with a boot control.

Class E: agent overstepped its authority

FailureSymptomRule now
Design made by agentsAgents shipped dialogue tone, credits, endings and rule changes. A diagnosis-only task became 38 commits.The owner decides these (document 3).
"Dead" code deletedAn agent removed movement code that one branch did not use. Another branch needed it.Ask before removing code.
Shared program stoppedAn agent closed another agent's emulator.Stop only processes that you started.
Work in progress lostA file checkout destroyed 54 translation entries and 35 collision rows.Do not check out tracked data files. Recover against a recorded digest.

Class F: the emulator hid the fault

FailureSymptomRule now
Hang not seenA console freeze did not occur in the usual emulator. That emulator skips bad graphics commands.Reproduce hangs in an accurate emulator (ares). Emulator results do not replace real hardware.

Smaller recorded costs

  • A wrong build target cost about an hour.
  • Wrong test-tool options cost hours of emulation.
  • Non-ASCII text in C source costs one full build each time. The rule: C source is ASCII only.
