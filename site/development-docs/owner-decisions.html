What the human decides

Purpose: define the decisions that an agent must not make, and the record that agents check before they act.

Summary

Agents can make technical choices. They must not make choices about what the game is. These choices stay with the owner. The owner records each decision in one place, and agents check that record before they act.

Decisions reserved to the owner

TypeExamples
CreativeDialogue text and tone, music, Mario's voice, visual identity, camera feel, title and credits
Gameplay rulesHow a mask, an item or a form behaves; progression
Content cutsRemoving content to save memory or time
Open designsDesigns not yet decided, for example a new game mode
ReleaseWhen to publish, and on which channel
ScopeTurning a diagnosis into a fix. A diagnosis-only task means diagnosis only.

Procedure

  1. The agent finds a choice in its work.
  2. If the choice is not of a reserved type, the agent decides and continues.
  3. If it is a reserved type, the agent checks the decision record.
  4. If the record has a decision, the agent follows it.
  5. If not, the agent stops and asks the owner. The owner's answer goes into the record.

If a test fails because of a deliberate design choice, the agent does not remove the behavior. It reads the history of the feature and asks the owner. A test does not outrank a decision. Some deliberate choices are recorded so that agents do not "fix" them, for example a joke in one character's dialogue and dialogue that is cryptic on purpose.

Decision record

  • The owner answers decisions in a local decision deck: one card for each question, with status, choice, note and date. The deck is under version control.
  • A generator turns the deck into a written specification.
  • The specification states that code, tests or dialogue that contradict a decision are wrong, not the decision.

What happened when agents decided

An audit on 2026-09-25 found that agents had made reserved decisions without approval:

  • Agents shipped dialogue tone, credits text, a character animation, ending changes and rule changes with no recorded approval.
  • Of 230 dialogue blocks that agents wrote, 20 had owner approval.
  • One diagnosis-only task grew into a merge of 38 commits and 160 files.

After the audit, the reserved types became a written rule in the agent instructions, and the decision deck became the record.

How the owner sets priorities

  • Work is ordered by how much information each step gives, not by calendar dates.
  • The connections between features (transitions, handoffs) must work from end to end before any one feature is polished.
