Corrections become tests

Purpose: make sure that the same correction is not needed twice.

Summary

A correction in a conversation is lost when the conversation ends, and the next agent makes the same mistake. Thus a correction is complete only when it is a test, a gate, or a rule that every later session reads.

Procedure

  1. Reproduce the fault. If an earlier fix failed, revert it first.
  2. If the behavior may be deliberate, ask the owner. Record the exception so that later audits do not undo it.
  3. Write the lesson: what happened, why, and how to apply it.
  4. If a program can check the rule, write a gate. Prove that it fails on the old code.

Lessons are kept as short notes, one per file, with an index that loads into each new agent session. Standing rules go into the instruction files that every agent reads first.

Agent failure patterns

Most corrections on this project came from a few repeated patterns.

PatternRule it produced
A confident cause that a control later disprovedMeasure a healthy build first
A second fix stacked on a failed fixRevert the failed fix, then instrument
A measurement of an old buildRebuild before every measurement
A proxy measured instead of the thingA gate must fail on the old code
A deliberate design "fixed" by an agentAsk before changing intent; record exceptions
A generic test trusted over a design decisionConfirm intent, then update the test
Work redirected to an easier goalThe task states non-goals; the owner rescopes
